# Encrypted Photo Vault — EPV1

Рабочая **Windows/Python-утилита** и **исходный Android-проект** для хранения произвольных файлов в Google Фото в виде зашифрованных PNG с цветным шумом.

**Состояние проекта:** Python-часть испытана автоматическими тестами. Криптографическое ядро Java/Android (`EpvCore.java`) проверено на совместимость с Python в обе стороны. Android APK собирается через GitHub Actions. Версии до 0.2 протестированы пользователем на Android; функции 0.3 требуют отдельной проверки на устройстве.

## Windows

1. Установить [Python 3](https://www.python.org/downloads/) с `py` launcher.
2. Распаковать архив в удобное место.
3. Дважды щёлкнуть `Start-EPV-Windows.bat` — установятся библиотеки и откроется графическое окно.
4. Ввести пароль. Выбрать исходные фотографии/видео или папку. Указать выходную папку для PNG.
5. Передать созданные PNG на **Pixel XL первого поколения** (USB, Syncthing, локальная сеть и т. п.), разместить в папке картинок и включить её резервное копирование в Google Фото. Использовать **исходное качество**.
6. Для восстановления скачать все PNG файла, указать папку и правильный пароль в программе.

Альтернативно, из PowerShell в папке проекта:

```powershell
py -m pip install -r requirements.txt
py -m epv encrypt "C:\Users\You\Pictures" -o "C:\EPV_PNG"
py -m epv inspect "C:\EPV_PNG"
py -m epv restore "C:\EPV_PNG" -o "C:\Recovered"
```

Чтобы проверить **сохранность пикселей после Google Фото**:

```powershell
py -m epv cloudcheck "C:\EPV_PNG" "C:\Downloaded_From_Google_Photos"
```

Здесь сравниваются именно RGB-байты, а не метаданные PNG.

## Android

Проект Android Studio расположен в `android/`. Это приложение без root и без доступа к интернету:

- **Шифрование файлов или целой папки:** кнопки «Выбрать файлы и зашифровать» и «Выбрать папку и зашифровать всё». Папка обходится рекурсивно; все обычные файлы (включая файлы в подпапках) шифруются по очереди. Исходные файлы остаются без изменений, зашифрованные PNG сохраняются в `Pictures/EncryptedPhotoVault` (MediaStore).
- Служебная папка `EncryptedPhotoVault` и PNG, уже имеющие имена частей EPV1, пропускаются во избежание повторного шифрования собственных результатов. По окончании показывается число успешно обработанных файлов и ошибки.
- **Восстановление** скачанных PNG в `Download/EncryptedPhotoVault` (открытые оригиналы). Для файлов, зашифрованных из папки в Android, восстанавливается вложенная структура каталогов: её относительный путь хранится внутри зашифрованных метаданных EPV1.
- **Приватная галерея:** расшифровка фотографий в памяти и чтение видео по частям через `MediaDataSource`, без экспорта открытого видео.
- Для выбора файлов/папок используется системный Android-проводник.

**Собрать APK:** открыть вкладку Actions репозитория → `Android debug APK` → выбрать успешный запуск → скачать артефакт `EncryptedPhotoVault-debug-apk`. Либо открыть папку `android/` в Android Studio и собрать `assembleDebug`.

Совместимость: Android 10+; версия Android 0.5.0, исходники Kotlin/Java, AGP 8.13.2, Kotlin 2.3.0. Учтите: подписанный случайным debug-ключом GitHub Actions APK может не устанавливаться поверх предыдущей debug-сборки из-за несовпадения подписи. В таком случае для тестирования потребуется удалить старую версию приложения (предварительно убедившись, что нужные оригиналы и PNG сохранены).


## Интеграция Google Фото / Vector

- **Google Фото → Поделиться → Encrypted Photo Vault**: выбранные фото/видео передаются во временный SAF-доступ приложения, после ввода пароля можно нажать «Зашифровать полученные через Поделиться». Фото исходно остаются в Google Фото, новые EPV PNG появляются локально. Важно: Google может передать перекодированную копию вместо исходных байтов.
- Для **Vector / LSPosed** добавлен отдельный Xposed APK `android/vector-bridge` — две кнопки поверх Google Фото: **EPV** (открывает EPV для выбора облачных PNG) и **18+** (локальный поиск в доступной папке). Модуль использует только scope `com.google.android.apps.photos`.
- Инструкция по установке и ограничения: [README_VECTOR.md](README_VECTOR.md). Не устанавливайте APK модуля через KernelSU — это **Xposed APK**, который нужно включить в Vector Manager.

## Новое в Android 0.3

### Приватная галерея
- Режим папки: открыть папку с EPV1 PNG через `Открыть зашифрованную галерею`. Есть сетка миниатюр, полный просмотр фото с масштабированием и воспроизведение видео из шифрованных частей.
- Режим Google Фото: `Выбрать зашифрованные PNG из Google Фото` открывает системный **Android Photo Picker**. При включённом облачном провайдере Google Фото можно выбрать загруженные PNG **без ручного скачивания в отдельную папку**. Нужны **все части** EPV1 (для большого видео это много PNG).
- Photo Picker/облачный провайдер временно получает данные из сети и может кешировать их внутри Android; утверждать, что передачи байтов нет, нельзя. Сами расшифрованные оригиналы в Download при просмотре не сохраняются.
- **Ограничение Google:** начиная с 2025 года сторонний клиент не может перечислить *всю* библиотеку Google Фото через Library API. Видны только файлы, выбранные пользователем. Для системного выбора требуется настройка Google Фото как облачного провайдера в Android Photo Picker. Некоторые провайдеры могут выдавать изменённые PNG — тогда проверка EPV1 отклонит такой файл.
- Выбор за одну операцию ограничен 100 изображениями. Источник действует в рамках текущей сессии приложения; чтобы повторно открыть файлы позже, их потребуется выбрать снова.

### Остановка и возобновление 18+ (Android 0.4)

- `Выбрать папку и запустить поиск 18+` — запоминает папку с постоянным разрешением на чтение и начинает классификацию.
- `Остановить поиск 18+` отменяет текущую задачу. Для прерванного файла неполные PNG удаляются штатным обработчиком; **только законченные** проверки фиксируются в локальной SQLite-базе.
- `Продолжить с последнего файла` повторно обходит выбранную папку, но пропускает уже обработанные документы. Сохранение отдельного индекса позволяет не зависеть от изменения порядка файлов. Прогресс сохраняется после закрытия приложения или перезагрузки устройства.
- `Сбросить прогресс` позволяет выполнить анализ заново. Изменение порога создаёт отдельный набор контрольных отметок, поэтому ранее пропущенные фото не считаются проверенными при новом пороге.
- Для обнаружения изменённых файлов контрольная отметка учитывает URI, размер и время изменения, сообщаемое Android-провайдером.
- **Используйте тот же пароль при продолжении**: шифрованные файлы предыдущей сессии могут иметь другой пароль, если вы его измените.
- Прогресс хранится в приватных данных приложения: удаление приложения или очистка его данных удалит историю проверок. Переустановка GitHub debug APK с другой подписью может потребовать удаления приложения и также сбросит прогресс.
- После аварийного прекращения процесса между экспортом PNG и фиксацией контрольной отметки возможен повторный экспорт одного файла. В штатном режиме «Остановить» такой сценарий минимизирован.

### Локальная классификация 18+
- `Найти 18+ в папке и зашифровать` — анализирует изображения и несколько кадров из каждого видео **полностью офлайн** с моделью TensorFlow Lite в APK.
- Используется MobileNetV2 на базе проекта [GantMan/nsfw_model](https://github.com/GantMan/nsfw_model), классы `drawings, hentai, neutral, porn, sexy`; оценка 18+ — сумма `hentai + porn + sexy`.
- Ползунок порога 50–98%, по умолчанию 70%. Это неточная ML-оценка, а не достоверный способ определить возраст людей.
- Шифруются только файлы с оценкой выше порога; остальные пропускаются. **Оригиналы не удаляются** даже после шифрования.
- Для видео берутся отдельные кадры (начало, середина, около 90%); 18+ фрагменты в других местах могут быть пропущены.
- Если модель не была включена в APK или не запустилась, приложение покажет ошибку, а не заявит, что всё проверено.
- Модель загружается из публичного репозитория в **GitHub Actions при сборке APK** и затем встроена в APK. Во время работы приложения она не скачивается и не отправляет изображения на сервер. Происхождение: GantMan/nsfw_model, лицензия MIT, см. `MODEL_LICENSE.md`.

**Безопасность:** определение 18+ нельзя использовать как единственный способ найти и защитить все чувствительные файлы. Режим не удаляет оригиналы, шифрование защищает копии, а не исходные фотографии в исходной папке.


## Технические свойства

- AES-256-GCM + Argon2id (64 MiB, 3 прохода). Каждый файл получает случайные соль и идентификатор; каждая часть — независимый случайный nonce.
- Данные и исходные имена/типы/размеры/хеши находятся внутри зашифрованной части, а не в PNG-метаданных.
- До 8 МиБ исходного файла на один PNG, размер картинки до 2048×2048.
- Для восстановления не требуется отдельный манифест. Части группируются по внутреннему ID, независимо от их имён и порядка.
- Неверный пароль и изменения пикселей детектируются проверкой аутентичности; восстановленный файл проверяется также по размеру и SHA-256.
- Скрыть количество PNG и примерный суммарный размер невозможно.

## Сортировка 18+ без шифрования (Android 0.5)

В EPV появилось отдельное действие **«18+ → отдельная папка (без шифрования)»**. Выбираются **две локальные папки** через стандартный Android-проводник: откуда сканировать и куда переносить. Пароль шифрования не нужен.

1. Выбери исходную папку с фото/видео и папку назначения.
2. Установи порог оценки 18+ (по умолчанию 70%).
3. Нажми **«Найти 18+ и переместить / продолжить»** и подтверди перенос оригиналов.
4. Для остановки нажми **«Остановить перенос»**, а для возобновления — ту же кнопку запуска.
5. Приложение сохраняет вложенные подпапки в каталоге назначения, пропускает остальные файлы и запоминает обработанные элементы в локальной SQLite-базе.

**Как именно перемещаются файлы:** приложение сначала копирует оригинальные байты без конвертации, повторно считывает полученный файл и сверяет размер и SHA-256, только затем удаляет исходник. Когда провайдер Android запрещает удаление, копия остаётся в папке назначения, оригинал не удаляется, а результат отмечается как «только скопировано». Прерванные и повреждённые копии удаляются по возможности, оригинал сохраняется.

**Внимание:** определение 18+ — вероятностная оценка. Возможны ошибки. Сделай резервную копию перед запуском режима с удалением исходников. Данные перемещаются только в **локальной файловой системе Android**, не между альбомами в облачном Google Фото: его API не позволяет стороннему приложению бесконтрольно читать и переносить всю библиотеку. Если провайдер не даёт права на удаление, полного переноса не произойдёт. Режим шифрования EPV остаётся отдельным и прежним.

## Важно

**Не удаляйте оригиналы**, пока не протестировали полный путь *шифрование → загрузка с Pixel XL → скачивание → cloudcheck → восстановление*. Возможность безлимитного исходного качества на оригинальном Pixel официально предусмотрена Google, однако сохранность всех пикселей после фактического экспорта необходимо испытать отдельно. Если пароль потерян, восстановить файлы нельзя. Код пока не проходил независимый аудит, не используйте проект как единственный архив важных данных.

`sample/` содержит пример с известным паролем `example-password-not-for-real-data` и инструкцией, как испытать Google Фото. Этот пароль нельзя использовать для настоящих секретов.
